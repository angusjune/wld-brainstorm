# WLD Simplify

Strip a WLD screen down to its essential elements. Remove everything that doesn't directly help the user complete their task.

**Core principle:** Every element on screen must earn its place. If removing it doesn't hurt task completion, remove it.

---

## When to Run

- **Automatically** after generating any screen in the `brainstorm` skill
- **On request** when user says "simplify", "clean up", "too busy", "too cluttered"
- **On Figma designs** when user provides a Figma URL to simplify

---

## Product Correctness Pass

**Run this BEFORE the visual Simplify Pass.** Visual stripping must not violate product rules.

1. Read `<plugin-root>/plugins/wld-design/assets/product-memory.md` to find the screen's COMP_ID.
2. If no COMP_ID is mapped, skip this pass.
3. Otherwise, load matching entries from `<plugin-root>/plugins/wld-design/assets/pm-memory-cache/common-pitfalls.yaml` per the bridge file's filter rule. (The cache is generated by `scripts/sync-pm-memory.sh`; never hand-edit it.)
4. For each loaded pitfall, verify the screen does NOT exhibit it. Examples currently in the KB for `COMP_WLD_LOAN_AMOUNT`:
   - **PIT-001:** Empty-state bottom CTA must be disabled (浅黄色), not active. The empty state must NOT connect to a SUBMITTING state.
   - **PIT-002:** Bottom sheets / overlays are independent screens. If a sheet exists, there must be a separate screen for the sheet open and the sheet closed.
   - **PIT-003:** 首借 keyboard CTA is 「确定」 (collapses keyboard only); 非首借 keyboard CTA is 「下一步」 (submits directly). These are two states, not one.
5. If a pitfall is detected, fix the screen (or raise to PM with the pitfall ID if ambiguous).
6. Loaded patterns and pitfalls are **must keep / must hold** — they override anything the visual Simplify Pass would otherwise strip.

## The Simplify Pass

For each screen, evaluate every element against these 5 questions:

### 1. Does the user need this to complete their task?

If no → remove it.

| Keep | Remove |
|------|--------|
| Amount input field | Decorative background patterns |
| "确认借款" CTA button | "Powered by WeBank" footer text |
| Bank account selector | Promotional banner (unless it's the point of the screen) |
| Error message | Redundant "提示" labels before self-explanatory content |
| Navigation back button | Secondary nav items not relevant to current flow |

### 2. Is this text saying something the user doesn't already know?

If no → remove or shorten it.

| Before | After | Why |
|--------|-------|-----|
| 请输入您的借款金额（单位：元） | 借款金额 | "请输入" is obvious, "单位：元" is shown by ¥ |
| 您的申请已成功提交，我们将在1-3个工作日内完成审核 | 申请已提交，1-3个工作日审核 | Same meaning, half the words |
| 点击下方按钮进行下一步操作 | _(remove entirely)_ | The button is right there |
| 温馨提示：请确保您的银行卡信息正确 | _(remove entirely)_ | Nobody reads these |
| 利率说明：年利率（单利）10.8%，... | 年利率 10.8% | Keep the number, drop the explanation |

### 3. Are there competing elements fighting for attention?

If yes → establish one clear focal point per screen.

**Rules:**
- One primary CTA per screen (gold button). Never two equal-weight gold buttons.
- One main number/metric per screen (the 44px WeChat Sans display).
- If there's a promotional banner AND a CTA, the CTA wins — dim or remove the banner.
- Navigation elements should fade into the background, not compete with content.

### 4. Is this visual decoration or functional?

If decorative → remove it.

| Decorative (remove) | Functional (keep) |
|---------------------|-------------------|
| Background dot/triangle patterns | Divider lines between list items |
| Gradient overlays on cards | Status icon (success/error) |
| Shadow on elements that don't need elevation | Card shadow (establishes hierarchy) |
| Icon next to text that already explains itself | Bank icon in account selector |
| Colored tags that repeat info from nearby text | Orange "限时" tag (unique info) |

### 5. Can two elements become one?

If yes → merge them.

| Before (2 elements) | After (1 element) |
|---------------------|-------------------|
| "可借额度" label + "¥60,000" amount | "可借 ¥60,000" (label inline) |
| Info icon (i) + tooltip text | Just the text |
| Section title + section subtitle | One line with both |
| "借款期数" label + "24个月" value + arrow | "借款期数 24个月 >" (one row) |

## Simplify Checklist

Run this for every screen:

```
□ Remove all background decorations (dots, triangles, gradients)
□ Remove "温馨提示" / "请注意" / "提示" boilerplate text
□ Remove "请输入" / "请选择" prefixes — placeholder text is enough
□ Shorten all body text to ≤15 characters where possible
□ Remove footer disclaimer text (unless legally required)
□ Ensure only ONE primary gold CTA per screen
□ Remove icons that duplicate adjacent text meaning
□ Merge label + value into single line where possible
□ Remove empty/spacer elements that don't aid hierarchy
□ Check: can any two adjacent elements become one?
□ Remove all emojis
```

## Applying to Different Sources

### After `brainstorm` generates a screen

1. Read the generated HTML
2. Run through the 5 questions above for each element
3. Edit the HTML to remove/simplify elements
4. The browser auto-reloads

### On existing Figma designs

First read `<plugin-root>/plugins/wld-design/assets/figma-mcp.md` for provider-neutral Figma MCP discovery, URL parsing, read flow, and write-back rules.

1. Use the available Figma MCP `get_design_context` tool to read the screen
2. Identify elements to remove/simplify
3. Use the available Figma MCP editing tool to edit the Figma file:
   - Delete decorative nodes
   - Shorten text nodes
   - Remove redundant frames
   - Merge label+value text nodes

## Boundaries: What NOT to Remove

Never simplify away:

- **Product rules from bundled memory** — anything loaded by the Product Correctness Pass (state splits, sheet variants, CTA-disabled rules, default-selection rules)
- **Legal/compliance text** — interest rate disclosures, agreement links (required by regulation)
- **Error states** — validation messages, failure explanations
- **Accessibility** — don't remove text alternatives, contrast, or tap targets
- **Navigation** — back button, tab bar (users need to leave the screen)
- **The primary CTA** — the whole point of the screen
- **Status indicators** — loading, success, error icons
- **Data the user entered** — form values, selected options

**When in doubt:** Ask "if I remove this, can the user still complete their task?" If no, keep it.
