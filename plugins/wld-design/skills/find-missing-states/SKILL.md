# WLD Find Missing States

A designer points at a screen they're working on (e.g. 输入金额页) and a Figma file with a redesign. The skill compares the Figma frames to the canonical state machine in the bundled spec and lists what the redesign hasn't covered yet.

**Core principle:** The bundled spec (`pm-spec-cache/components/{COMP_ID}.yaml`) is the source of truth for which states a WLD page has. Anything in the spec but missing from Figma is a candidate "missing state."

---

## When to Use

- Designer says: "I'm redesigning 输入金额页, what am I missing?"
- Designer says: "缺失状态" / "missing states" / "state coverage" / "完整性检查"
- After a designer shares a new Figma link for an existing WLD page

## When NOT to Use

- **Brand-new screen** with no spec yet → use `wld-design:brainstorm` first
- **Visual cleanup** of a single screen → use `wld-design:simplify`
- **Non-WLD products** → this skill is WLD-specific (it depends on bundled `COMP_WLD_*` specs)

---

## Inputs (collect both before starting)

1. **Page name** — Chinese name (e.g. 输入金额页) or English (e.g. "loan amount page")
2. **Figma link** — full URL with file key, ideally with a node-id

If the user only gives one, ask for the other in a single message. Do not start the analysis with partial inputs.

---

## Workflow

```
1. Resolve page → COMP_ID (via index.yaml)
2. Load spec's state_machine + common-pitfalls
3. Read Figma frames (MCP) or accept a frame list from the designer
4. Match each Figma frame to a spec state_id
5. Compute three diffs (missing / extra / pitfall violations)
6. Output structured report
```

### Step 1: Resolve Page Name → COMP_ID

Read `assets/pm-spec-cache/index.yaml` and find the entry where `component_name` matches the page name (Chinese or English). Capture:

- `component_id` (e.g. `COMP_WLD_LOAN_AMOUNT`)
- `spec_path` (e.g. `knowledge-base-spec/components/COMP_WLD_LOAN_AMOUNT.yaml`) — **for reference only**; read the bundled cached copy

The cached spec file lives at `assets/pm-spec-cache/components/{COMPONENT_ID}.yaml`.

**If no match:**
- Check `assets/product-memory.md` (Screen ↔ COMP_ID mapping table) for an alias
- If still no match, tell the designer: "No bundled spec exists for this page yet. I can still apply WLD common-pitfalls and BENS framework heuristics — proceed?" Wait for confirmation.

**If `assets/pm-spec-cache/` is missing** (rare; means a broken install): stop and tell the user the bundled plugin cache is missing or incomplete.

### Step 2: Load Spec State Machine + Pitfalls

**Spec:** Read the YAML at `assets/pm-spec-cache/components/{COMPONENT_ID}.yaml`. Spec files can be 1000+ lines — use `grep` or limited Read to extract only `state_machine`. For each state collect: `state_id`, `state_name`, `state_type`, `entry_conditions`, `notes` (often contains Figma node refs like "Figma ref 22415-48845").

**Pitfalls:** Read `assets/assets/pm-memory-cache/common-pitfalls.yaml`. Filter entries where `source` references the resolved COMP_ID. Each entry has: `pitfall_id`, `description`, `detection`, `correction`. These are MUST-HOLD rules — a redesign that violates one is missing a state regardless of what the spec says.

Both caches are generated by `scripts/sync-pm-memory.sh` — never hand-edit them.

### Step 3: Read Figma Frames

**Reading the Figma file is the load-bearing step of this skill.** Without frames, there is no diff — only a checklist. Treat any failure here as loud and visible, never silent.

Before using Figma MCP, read `<plugin-root>/plugins/wld-design/assets/figma-mcp.md` for provider-neutral tool discovery, URL parsing, metadata/context usage, large-file handling, and fallbacks.

Decision order:

1. **Figma MCP available** (any tool name containing `figma`, e.g. `mcp__figma__*` or a provider-specific Figma namespace) — preferred path:
   - Parse the file key + node id from the URL (e.g. `figma.com/design/{fileKey}/...?node-id={nodeId}` — convert `-` to `:` in the nodeId)
   - Call `get_metadata` on the file/node to enumerate frames with names + node_ids. **For files with 30+ top-level frames, the response can exceed the 25k-token tool-output limit.** Save the JSON to a temp file via Bash and use `jq '.. | objects | select(.type? == "FRAME") | {name, id}'` (or similar) to extract just the frame list.
   - For each frame, call `get_design_context` for visual content. This usually returns the structured layout, text content, and design tokens you need for matching.
   - `get_screenshot` is **optional** — only fall back to it when `get_design_context` doesn't give enough information to disambiguate (e.g. visual-only state cues like CTA color). Skip it by default; in some MCP setups it fails with TLS/certificate errors anyway.
   - Proceed to Step 4 with the full frame list.

2. **No Figma MCP, but the designer is in the loop** — ask once, in this exact form:
   > "I don't have a Figma MCP available. Paste the frame list as text (e.g. `「未输入-高额度」, 「输入中-首借」, ...`) and I'll do a name-based diff."
   - If the designer responds with a list, proceed to Step 4. Note in the final report header: `Source: name-only — no visual confirmation`.

3. **No Figma MCP and no designer response** — STOP. Do NOT silently fall through to Step 4 with zero frames. Switch to **Spec-Only Walkthrough mode** (see Step 6B). The output is explicitly labeled as a different report type — a spec checklist, not a diff. Tell the user upfront: "Skill cannot produce a diff without the Figma frames. Producing a spec walkthrough instead."

**Never produce a 'missing states' diff with zero frames matched.** That output is misleading — every state appears missing because nothing was checked, not because nothing exists. If you find yourself with zero matched frames, you must be in mode 3 (Spec-Only Walkthrough), and the report header must say so.

### Step 4: Match Figma Frames → Spec States

For each Figma frame, find the best-matching spec state using this priority:

1. **Exact name match** — frame name == `state_name` (e.g. frame "未输入-高额度" → `STATE_LOAN_AMOUNT_EMPTY_HIGH`)
2. **Node-id reference** — spec `notes` contains "Figma ref {node_id}" matching the frame's node_id
3. **Substring / keyword** — frame name contains the state's distinguishing keyword (e.g. "已输入" matches `EDITING_*`)
4. **Visual content** — frame's elements match `entry_conditions` + `notes` description

**Mark ambiguous matches** — if a frame could match 2+ states (e.g. "已输入" → `EDITING_FIRST` or `EDITING_RELOAN`), record both and ask the designer in the final report.

**Never silently guess.** Either match confidently or list as ambiguous.

### Step 5: Compute Four Diffs

Before assigning a frame to any bucket, ask: **is this a 1:1 relationship with a single spec state, or an N:M relationship?** N:M relationships go in the new Divergent bucket — never in Matched, Missing, or New. Without this rule, items get double-counted (a merged drawer is "matched" to two states, AND those two states each get listed as "missing" because neither is independently represented).

**A. Matched states** (1:1)
- A Figma frame that maps cleanly to exactly one spec state.
- Confidence ranks: `high` (exact name or node-id ref) / `medium` (keyword + visual confirm) / `ambiguous` (could match 2+ states equally — record the candidates, don't pick)

**B. Design divergences** (N:M — semantic restructure between spec and redesign)
Three sub-types:
- **Merge** — N spec states fold into 1 Figma frame (e.g. spec separates 期数浮层 from 还款计划浮层; redesign combines them into one drawer)
- **Split** — 1 spec state expands into N Figma frames (e.g. spec has one EMPTY_LOW; redesign splits it into 不足1万 / 不足2万 buckets)
- **Reframe** — different axis of variation (e.g. spec slices by 首借/非首借; redesign slices by credit-line tier)

For each divergence, list spec state(s) involved, Figma frame(s) involved, and a question for the designer ("intentional? if yes, spec needs updating"). **Items in Divergent are EXCLUDED from Matched, Missing, and New.**

**C. Missing states** (in spec, no representation in Figma — even partial)
- States in `state_machine` with no matched Figma frame AND not part of any divergence
- Group by category: entry variants, input states, errors, sheets/overlays, sub-states

**D. New states in Figma not in spec**
- Figma frames that didn't match any spec state AND aren't part of any divergence
- These are either: (a) intentional new states for the redesign (designer should confirm), or (b) re-named existing states (designer needs to align names)

**Common-pitfall violations** (run alongside the four diffs)
- For each loaded pitfall, check whether the Figma set could violate it
- Example: PIT-002 (every sheet/overlay is its own state) — for every state in `state_machine` whose `state_type` is `sheet` or `dialog`, there must be a dedicated Figma frame. If Figma has only one sheet frame but the spec lists multiple sheet states, each missing one is a violation.
- Example: PIT-003 (首借/非首借 keyboard CTA differs) — if Figma has only one 「输入中」 frame, flag as missing the second variant
- Example: PIT-001 (empty-state CTA must be disabled) — if visuals are available, verify the empty-state frame's bottom CTA is 浅黄色 (disabled). If no MCP, flag as a rule the designer must self-verify.

### Step 6: Output Structured Report

Pick the format based on which Step-3 mode you ended up in:

- **Mode 1 or 2** (you have a frame list — MCP or designer-pasted): use **6A: Diff Report** below.
- **Mode 3** (no frames — degraded fallback): use **6B: Spec-Only Walkthrough** below. Do NOT use 6A with zero frames.

#### 6A: Diff Report (Chinese-friendly, since designers work in Chinese)

```markdown
# 缺失状态分析报告 — {page_name}

**Spec:** `{spec_path}` ({N} states defined)
**Figma frames analyzed:** {M}  ·  **Source:** {Figma MCP / name-only from designer}
**Matched:** {X} · **Divergent:** {D} · **Missing:** {Y} · **New (not in spec):** {Z}

> Counts must not double-count: every frame and every spec state appears in exactly one bucket.

## ✅ Frames matched to spec states (1:1)
| Figma frame | → | Spec state | Confidence |
|---|---|---|---|
| 输入金额-空态 | → | STATE_LOAN_AMOUNT_EMPTY_HIGH (未输入-高额度) | high |
| 输入金额-已输入 | → | STATE_LOAN_AMOUNT_EDITING_FIRST OR _RELOAN | ⚠️ ambiguous |

## 🔀 Design divergences (intent confirmation needed)

These are N:M relationships between spec and redesign — neither matched 1:1 nor missing nor net-new. Each row is a candidate spec update if confirmed intentional.

| Type | Figma frame(s) | Spec state(s) | Question for designer |
|---|---|---|---|
| Merge | 「怎么还」 (5:557 + variants) | TENOR_STANDARD, REPAYMENT_LOADED | Intentional merge of 期数选择 + 还款计划 into one drawer? If yes, spec needs to collapse. |
| Split | 输入金额-不足1万 / 不足2万 / -键盘 / -利息试算 | EMPTY_LOW | Are 不足1万 vs 不足2万 distinct states, or sub-variants of one? Spec currently has only HIGH/LOW. |
| Reframe | All keyboard frames (CTA all show 「下一步」) | EDITING_FIRST vs EDITING_RELOAN | Spec slices by borrower-type; redesign slices by credit-line tier. Confirm which axis is intended. |

## ⚠️ Missing states (in spec but not in Figma — and not part of any divergence above)
Grouped by category. Each line: `state_id` (state_name) — one-line why-it-matters.

### Entry / empty variants
- `STATE_LOAN_AMOUNT_EMPTY_LOW` (未输入-低额度) — low credit-line layout differs
- `STATE_LOAN_AMOUNT_AUTOFILLED` (已带入金额) — first-time borrower, amount pre-filled, keyboard does NOT auto-pop

### Input states
- `STATE_LOAN_AMOUNT_EDITING_RELOAN` (输入中-非首借) — keyboard CTA is 「下一步」 not 「确定」 (PIT-003)

### Validation errors
- ...

### Sheets / overlays (each is an independent state — PIT-002)
- ...

### Async loading / error
- ...

## 🆕 New frames in Figma not matched to any spec state
- 「{frame name}」 — could be: (a) new state for redesign (please confirm), (b) renamed existing state

## 🚨 Common-pitfall violations
- **PIT-002** (sheets are independent states): Figma has 「期数浮层」 but no separate frame for the page with the sheet closed. Add a "sheet closed" companion frame for each overlay.
- **PIT-003** (首借/非首借 keyboard CTA differs): Only one 输入中 frame found — add the second variant.

## Next actions for the designer
1. Confirm the ambiguous matches above
2. Decide whether to redesign the missing states or scope them out
3. Resolve pitfall violations before sharing the redesign for review
```

#### 6B: Spec-Only Walkthrough (degraded mode — no frames available)

Use this when Step 3 ended in mode 3. The report MUST open with a loud header announcing this is NOT a diff. The designer should be able to tell at a glance.

```markdown
# ⚠️ Spec-Only Walkthrough (DEGRADED MODE) — {page_name}

> **This is NOT a missing-states diff.** The Figma file could not be read (no Figma MCP available + no frame list provided), so I cannot tell which states the redesign already covers. Below is a spec walkthrough of every state this page should support — use it as a checklist to tick against your Figma file by hand. Re-run this skill with a Figma MCP enabled, or paste a frame list, to get a real diff.

**Spec:** `{spec_path}` ({N} states defined, {N-T} relevant + {T} terminal handoffs)
**Figma frames analyzed:** 0
**Mode:** spec-only walkthrough (no diff possible)

## All states defined in spec — tick what you already have

Grouped by category. Each line: `state_id` (state_name) — one-line why-it-matters.

### Entry / empty variants
- [ ] `STATE_LOAN_AMOUNT_EMPTY_HIGH` (未输入-高额度) — ...
- [ ] `STATE_LOAN_AMOUNT_EMPTY_LOW` (未输入-低额度) — ...

### Input states
- [ ] ...

### {…remaining categories…}

### Terminal handoffs (NOT states of this page — listed for completeness)
- `STATE_LOAN_AMOUNT_SUBMITTING` (提交中) — `is_terminal: true`, jumps to next page

## Self-check rules (from common-pitfalls)

The pitfalls cannot be auto-checked without frames. The designer must self-verify:

- **PIT-001** — Empty/error states must have the bottom CTA in 浅黄色 (disabled). No transition to SUBMITTING from these states.
- **PIT-002** — Every sheet/dialog state in the spec needs its own dedicated frame. The spec lists {K} sheet/dialog states — the redesign must have at least {K} overlay frames.
- **PIT-003** — Two separate 输入中 frames are required: one for 首借 (键盘 CTA「确定」) and one for 非首借 (键盘 CTA「下一步」).

## To upgrade this report to a real diff

- Enable a Figma MCP and re-run, OR
- Paste your Figma frame list as text in this format: `「frame name 1」, 「frame name 2」, ...`
```

---

## Key Principles

- **Spec is source of truth** — never invent states. Every "missing" state must come from `state_machine` or a loaded pitfall.
- **One spec, one page** — don't merge analyses across multiple COMP_IDs in one report.
- **Ambiguity is information** — surface it, don't paper over it.
- **Read big specs in slices** — spec YAMLs can be 1000+ lines; grep for `state_id` first, then read details only for the states you flag.
- **Don't write to the cache** — bundled product knowledge is read-only during normal use.

---

## Common Mistakes

| Mistake | Fix |
|---|---|
| Listing generic UX states ("loading", "error") | Always cite `state_id` from the actual spec |
| Skipping common-pitfalls check | PIT-* rules override anything else — load them first |
| Auto-mapping ambiguous frames | Mark as ambiguous, ask designer to confirm |
| Reading the whole 1000-line spec | Grep for `state_id:` first, then read targeted slices |
| Hand-editing `assets/assets/pm-memory-cache/` | It is bundled product knowledge. Treat it as read-only during normal use. |
| Treating sheet states as UI of the parent | Sheets are independent states (PIT-002). Each needs its own frame. |
| Counting the "next page" (e.g. 成功页) as a state of this page | If `is_terminal: true` and notes say "跳转至下一页", it ends THIS component — not a missing state of this page |
| Starting analysis with only one input | Collect both page name AND Figma link before Step 1 |
| Producing a "missing states" diff with zero frames matched | This is misleading — every state appears missing because nothing was checked. Switch to Spec-Only Walkthrough mode (6B) and label the output loudly as degraded. |
