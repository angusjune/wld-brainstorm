# Brainstorm Solution Archetypes

Use this reference before generating the three-option `solutions.html` page. These are examples of directions to choose from, not fixed layouts. Keep visual execution grounded in the selected `profileDir/screens/` templates.

## Choose directions before detailing

Consider about five short candidates, then select three that offer useful differences for this request. Do this within the authoring task; no additional files or approval round are needed. For each selected direction, decide:

- the user benefit or visual hypothesis and its tradeoff;
- the dominant information and reading order;
- the composition: grouping, alignment, density, and relation of the primary action to its content;
- the corpus patterns worth borrowing and how they fit together.

Give each screen one coherent visual language. Establish its composition first, then refine type proportions, spacing, surfaces, and controls together. Use the same real data across the set so content changes do not masquerade as design variety. A direction earns its place through a perceptible or behavioral difference, not a new name or a different DOM wrapper.

## UX Strategy Archetypes

Use when the user is still exploring what the screen or flow should do.

Read the active profile's design language and any product-specific archetypes for directions that fit its screens.

When the profile lists none for the screen at hand, these generic lenses still apply — each makes a different thing the dominant object:

- **Task-first:** the next likely action is obvious from the user's state
- **Object-first:** the thing the user came for (the amount, the item, the status) dominates
- **Confidence-first:** foregrounds what the user needs to trust before acting — consequences, totals, what happens next
- **Guardrail-first:** eligibility, limits, disabled states, and risk are clear before action
- **Comparison-first:** helps weigh options against each other rather than picking blind
- **Verification-first:** makes it easy to check that the selection and totals are right

## Visual Exploration Archetypes

Use when the user asks for visual possibilities, style direction, or the flow is already fixed. These may share the same user journey.

- Calmer / native: closest to the platform's defaults, light separators, quiet hierarchy
- Premium / spacious: more whitespace, stronger focal treatment, fewer competing modules
- Compact / task-focused: denser rows, faster scanning, action close to the decision
- Data-forward: key numbers, dates, and terms become the main visual rhythm
- Softer / warmer: gentle surfaces and warmer secondary emphasis, staying inside the profile's palette
- Promotional but restrained: an offer is visible without urgency language, countdowns, or pressure

Every option must stay inside the profile's product laws, whichever archetype it follows.

## Caption Format

For UX Strategy mode:

```text
方案 A: Amount-first
Hypothesis: fastest path to borrowing
Tradeoff: less explanation upfront
```

For Visual Exploration mode:

```text
方案 A: Premium / spacious
Visual hypothesis: make the amount feel calmer and more trustworthy
What changes: larger whitespace, quieter cards, stronger single CTA
```

For Mixed mode, use two UX Strategy options and one Visual Exploration option, and label the visual one clearly.
